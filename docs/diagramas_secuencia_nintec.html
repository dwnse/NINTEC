Diagrama Troncal: Flujo Completo End-to-End de Compra y Despacho

Interacción completa desde la selección de producto en Android hasta la confirmación y entrega gestionada por el Administrador en la Web.

App Android Checkout 3 Métodos Supabase REST Admin Web 
sequenceDiagram
    autonumber
    actor C as Cliente (Android)
    participant UI as ProductDetailFragment
    participant CM as CartManager (Singleton)
    participant PAY as PaymentMethodFragment
    participant REPO as OrderRepository
    participant SUPA as Supabase PostgREST
    participant DB as PostgreSQL (orders, items)
    participant WEB as Consola Web (OrdersView)
    actor ADM as Administrador (Web)

    %% 1. Selección y Compra Directa
    C->>UI: Ajusta cantidad (- 1 +) y presiona "Compra Directa"
    UI->>CM: addToCart(product, quantity)
    CM-->>UI: Stock validado y cantidad agregada
    UI->>PAY: Navegación inmediata a PaymentMethodFragment
    
    %% 2. Checkout
    C->>PAY: Selecciona Método de Pago (Tarjeta / QR / PayPal) y Sucursal
    C->>PAY: Presiona "Confirmar y Pagar"
    PAY->>REPO: createOrder(orderData, items)
    
    %% 3. Validación y Persistencia
    REPO->>REPO: Validar formato UUID del usuario autenticado
    alt UUID Válido (Usuario Registrado en Supabase)
        REPO->>SUPA: POST /rest/v1/orders (user_id, total, branch_id, status='pending')
        SUPA->>DB: INSERT INTO orders
        DB-->>SUPA: 201 Created (order_id UUID)
        REPO->>SUPA: POST /rest/v1/order_items (order_id, product_id, qty, unit_price)
        SUPA->>DB: INSERT INTO order_items
        DB-->>SUPA: 201 Created
        REPO-->>PAY: Confirmación de orden registrada en la nube + Cache Local
    else Usuario Offline o Mock
        REPO->>REPO: Guardar orden en SharedPreferences con ID local generado
        REPO-->>PAY: Confirmación de orden respaldada en Cache Local Dual
    end

    PAY->>CM: clearCart()
    PAY-->>C: Renderiza OrderConfirmationFragment con Comprobante Digital

    %% 4. Consola Administrativa
    Note over ADM,WEB: Recepción y Despacho en Consola Web
    WEB->>SUPA: GET /orders?status=eq.pending
    SUPA-->>WEB: Lista de nuevos pedidos entrantes
    ADM->>WEB: Revisa comprobante y cambia estado a "confirmed"
    WEB->>SUPA: PATCH /orders?id=eq.uuid (status='confirmed')
    SUPA->>DB: UPDATE orders SET status = 'confirmed'

    %% 5. Notificación y Seguimiento en Cliente
    Note over C,UI: Seguimiento en Tiempo Real en App Móvil
    C->>UI: Abre Historial de Pedidos (OrderDetailFragment)
    UI->>REPO: getUserOrders(userId)
    REPO->>SUPA: GET /orders?user_id=eq.uuid
    SUPA-->>REPO: Retorna pedido con status = 'confirmed'
    REPO-->>UI: Actualiza Timeline visual de 4 pasos a "Confirmado"

Mensajes y Llamadas Clave

  • addToCart(p, q): Ejecución síncrona en memoria con validación de stock.
  • POST /orders y POST /order_items: Persistencia relacional atómica en Supabase.
  • PATCH /orders: Actualización reactiva de estado por el administrador.

Tolerancia a Fallos

  • Manejo de rama alternativa (alt) para usuarios con identificador local evitando errores HTTP 400.

Diagrama de Secuencia 1: Autenticación, Registro y Control de Acceso (RBAC)

Ciclo de vida del Login en pantalla completa estática, validaciones locales, autenticación JWT y asignación de rol.

LoginActivity SessionManager Supabase Auth Tabla users 
sequenceDiagram
    autonumber
    actor U as Usuario
    participant UI as LoginActivity (Full-Screen)
    participant SM as SessionManager (SharedPreferences)
    participant AUTH as Supabase Auth API (/token)
    participant DB as PostgreSQL (Tabla users)
    participant HOME as MainActivity (HomeFragment)

    U->>UI: Abre la aplicación
    UI->>SM: isLoggedIn()
    alt Ya existe sesión activa
        SM-->>UI: Retorna true + Token JWT + Rol guardado
        UI->>HOME: Redirige directamente al Home
    else No existe sesión
        SM-->>UI: Retorna false
        UI-->>U: Renderiza pantalla de Login estática (sin scroll rebotante)
        
        U->>UI: Escribe Email y Contraseña, pulsa "Ingresar"
        UI->>UI: Validar campos no vacíos y formato email
        
        alt Campos inválidos
            UI-->>U: Muestra mensaje de error en TextInputLayout
        else Campos válidos
            UI->>AUTH: POST /auth/v1/token?grant_type=password
            alt Credenciales Incorrectas (HTTP 400)
                AUTH-->>UI: Error: Invalid login credentials
                UI-->>U: Muestra Toast "Credenciales incorrectas"
            else Credenciales Válidas (HTTP 200)
                AUTH-->>UI: Retorna access_token JWT + user_id UUID
                UI->>DB: GET /rest/v1/users?id=eq.user_id
                DB-->>UI: Retorna { id, username, email, role: 'cliente' | 'admin' }
                UI->>SM: saveUserSession(token, user_id, username, role)
                SM-->>UI: Sesión almacenada exitosamente
                UI->>HOME: Inicia MainActivity
                HOME-->>U: Muestra Perfil con @username y Badge de Rol
            end
        end
    end

Participantes del Proceso

  • LoginActivity: Vista nativa a pantalla completa estática con overScrollMode="never".
  • SessionManager: Persistencia de claves de sesión en almacenamiento privado seguro.
  • Supabase Auth: Emisión de JSON Web Tokens (JWT) firmados.

Control de Roles (RBAC)

  • El rol obtenido de la tabla users determina el acceso al menú administrativo y el color del badge en el perfil.

Diagrama de Secuencia 2: Catálogo, Búsqueda Reactiva y Sincronización

Carga de categorías y banners, búsqueda por texto en tiempo real, filtrado de stock y fallback offline con Gson.

HomeFragment CatalogFragment ProductRepository Cache / Supabase REST 
sequenceDiagram
    autonumber
    actor C as Cliente
    participant HOME as HomeFragment
    participant CAT as CatalogFragment
    participant REPO as ProductRepository
    participant CACHE as SharedPreferences (Cache Gson)
    participant API as Supabase REST (/products, /categories)

    C->>HOME: Abre pestaña de Inicio
    HOME->>REPO: getFeaturedProducts() y getHeroBanners()
    REPO->>API: GET /rest/v1/banners?active=eq.true
    alt Conexión Exitosa
        API-->>REPO: Lista de banners y productos destacados (JSON)
        REPO->>CACHE: saveBannersCache(json) y saveProductsCache(json)
        REPO-->>HOME: Carga carrusel y ofertas
    else Falla de Red / Sin Conexión
        REPO->>CACHE: getCachedProducts()
        CACHE-->>REPO: Retorna datos previamente almacenados
        REPO-->>HOME: Renderiza productos en modo offline
    end

    C->>HOME: Toca chip de categoría "Laptops"
    HOME->>CAT: Navega a CatalogFragment(categoryId)
    CAT->>REPO: getProductsByCategory(categoryId)
    REPO-->>CAT: Retorna productos filtrados con stock y precios
    CAT-->>C: Renderiza lista en RecyclerView

    C->>CAT: Escribe "ASUS" en el SearchView
    CAT->>CAT: Aplica filtro reactivo en adapter (filterList)
    CAT-->>C: Actualiza tarjetas mostrando solo coincidencias

Mecanismo de Resiliencia

  • Arquitectura Cache-First con Network-Sync: Primero responde la memoria y luego actualiza en segundo plano.
  • La búsqueda local en el adapter no genera peticiones innecesarias al servidor, garantizando 60 FPS de fluidez.

Filtros Interactivos

  • Soporte de chips horizontales de categorías con selección única y botón de limpieza de filtros.

Diagrama de Secuencia 3: Gestión del Carrito de Compras (CartManager Singleton)

Adición rápida, incremento/decremento, control estricto de límite de stock y recálculo matemático de totales.

CartManager CartFragment ProductDetailFragment 
sequenceDiagram
    autonumber
    actor C as Cliente
    participant PROD as ProductDetailFragment
    participant CM as CartManager (Singleton)
    participant PREF as SharedPreferences (Cache Local)
    participant CART_UI as CartFragment (Mi Carrito)

    C->>PROD: Presiona botón "Añadir al Carrito" (cantidad seleccionada = 2)
    PROD->>CM: addToCart(product, 2)
    
    CM->>CM: verifyStockLimit(product.id, currentQty + 2, stockQuantity)
    alt Cantidad supera stock disponible
        CM-->>PROD: Retorna false (Stock insuficiente)
        PROD-->>C: Muestra Toast "Stock máximo disponible alcanzado"
    else Stock suficiente
        CM->>CM: actualiza lista interna de CartItems
        CM->>CM: recalculateTotals() -> subtotal, discount, total
        CM->>PREF: persistCartToDisk(Gson.toJson(cartItems))
        CM-->>PROD: Retorna true
        PROD-->>C: Ejecuta animación de badge superior y Toast de confirmación
        Note over PROD,C: El cliente permanece en la misma pantalla sin redirección
    end

    C->>CART_UI: Abre pestaña "Mi Carrito"
    CART_UI->>CM: getCartItems() y getTotalPrice()
    CM-->>CART_UI: Retorna lista y total calculado en Bs
    CART_UI-->>C: Muestra lista de ítems, selector (- 1 +) y total a pagar

    C->>CART_UI: Presiona botón (-) en un producto con cantidad 1
    CART_UI->>CM: updateQuantity(productId, 0)
    CM->>CM: Elimina el ítem de la lista
    CM->>CM: recalculateTotals()
    CM->>PREF: persistCartToDisk()
    CM-->>CART_UI: Notifica lista actualizada
    CART_UI-->>C: Muestra empty state "Tu carrito está vacío" si no quedan productos

Manejo de Estado en Memoria

  • CartManager actúa como única fuente de la verdad (Single Source of Truth) para el carrito.
  • La barra inferior y el badge superior se actualizan reactivamente al disparar eventos.

Persistencia en Disco

  • Cualquier cambio se serializa a JSON de forma asíncrona para que no se pierdan compras al apagar el celular.

Diagrama de Secuencia 4: Checkout Multi-Método y Persistencia Dual

Validación de formularios de Tarjeta, QR y PayPal, asignación de sucursal física, validación de UUID e inserción en Supabase.

PaymentMethodFragment OrderRepository orders & order_items 
sequenceDiagram
    autonumber
    actor C as Cliente
    participant UI as PaymentMethodFragment
    participant REPO as OrderRepository
    participant SUPA as Supabase REST (/orders, /order_items)
    participant CM as CartManager
    participant CONF as OrderConfirmationFragment

    C->>UI: Selecciona método de pago
    alt Tarjeta de Crédito / Débito
        C->>UI: Ingresa número de tarjeta, vencimiento (MM/AA), CVV y titular
        UI->>UI: Validar número de 16 dígitos y CVV
    else Código QR
        UI-->>C: Muestra imagen oficial QR y cuenta comercial NINTEC
        C->>UI: Ingresa código de referencia de pago y banco emisor
    else PayPal
        UI-->>C: Muestra instrucciones de pago a ninteclp@paypal.com
        C->>UI: Ingresa correo PayPal y código de transacción
    end

    C->>UI: Selecciona Sucursal (Central / Calacoto / El Alto) y notas
    C->>UI: Pulsa botón "Confirmar y Pagar"
    
    UI->>REPO: createOrder(userId, items, total, branch, paymentMethod, paymentRef)
    
    REPO->>REPO: isValidUuid(userId)
    alt UUID de Supabase Válido
        REPO->>SUPA: POST /orders { user_id, branch_id, total, status: 'pending', payment_method }
        SUPA-->>REPO: 201 Created con order_id
        loop Para cada ítem del carrito
            REPO->>SUPA: POST /order_items { order_id, product_id, quantity, unit_price }
            SUPA-->>REPO: 201 Created
        end
        REPO->>REPO: Guardar respaldo sincronizado en SharedPreferences
    else Usuario Offline o ID Local
        REPO->>REPO: Generar ID local No. NIN-XXXX y almacenar en SharedPreferences
    end

    REPO-->>UI: Pedido generado con éxito
    UI->>CM: clearCart()
    UI->>CONF: Navega a OrderConfirmationFragment(order)
    CONF-->>C: Muestra Comprobante Digital con sucursal y total pagado

Mapeo de Pasarelas

  • Tarjeta: Validación de máscara numérica, expiración y CVV.
  • QR: Verificación de código de comprobante bancario.
  • PayPal: Conciliación de ID de transacción digital.

Protección de Integridad Referencial

  • La validación estricta de UUID en OrderRepository evita que peticiones locales queden bloqueadas con error HTTP 400.

Diagrama de Secuencia 5: Ciclo de Vida del Pedido y Sincronización

Interacción de 4 fases (Pendiente ➔ Confirmado ➔ En Preparación ➔ Finalizado) entre el Administrador y la App del Cliente.

Admin Web Supabase PostgreSQL OrderHistoryFragment OrderDetailFragment 
sequenceDiagram
    autonumber
    actor C as Cliente (App Android)
    participant APP as OrderDetailFragment
    participant REPO as OrderRepository
    participant DB as PostgreSQL (orders)
    participant WEB as OrdersView (Consola Web)
    actor ADM as Administrador (Web)

    Note over C,DB: Fase 1: Pedido en Estado Pendiente
    DB-->>WEB: Pedido aparece en tabla con badge amarillo "pending"
    
    Note over ADM,DB: Fase 2: Validación Administrativa de Pago
    ADM->>WEB: Revisa comprobante QR / Tarjeta / PayPal
    ADM->>WEB: Selecciona nuevo estado: "Confirmado"
    WEB->>DB: PATCH /rest/v1/orders?id=eq.uuid { status: 'confirmed' }
    DB-->>WEB: 200 OK (Estado confirmado)

    Note over C,APP: Sincronización en la App del Cliente
    C->>APP: Abre detalle del pedido
    APP->>REPO: getOrderById(orderId)
    REPO->>DB: GET /rest/v1/orders?id=eq.uuid
    DB-->>REPO: Retorna status = 'confirmed'
    REPO-->>APP: Actualiza interfaz
    APP-->>C: Timeline avanza a "Confirmado" con indicador verde

    Note over ADM,DB: Fase 3: Despacho en Sucursal
    ADM->>WEB: Sucursal empaqueta productos y cambia a "En preparación"
    WEB->>DB: PATCH /rest/v1/orders?id=eq.uuid { status: 'in_preparation' }
    DB-->>WEB: 200 OK

    Note over ADM,DB: Fase 4: Entrega y Finalización
    ADM->>WEB: Cliente retira en sucursal o recibe delivery -> cambia a "Finalizado"
    WEB->>DB: PATCH /rest/v1/orders?id=eq.uuid { status: 'completed' }
    DB-->>WEB: 200 OK

    C->>APP: Recarga historial
    APP->>REPO: getUserOrders(userId)
    REPO->>DB: GET /rest/v1/orders?user_id=eq.uuid
    DB-->>REPO: Lista de pedidos con status = 'completed'
    REPO-->>APP: Renderiza tarjeta con badge azul "Finalizado"
    APP-->>C: Muestra Factura y Resumen Completo

Transición de Estados Oficial

  • pending (Pendiente): Registro inicial en base de datos.
  • confirmed (Confirmado): Pago verificado por el administrador.
  • in_preparation (En preparación): Almacén empaqueta artículos.
  • completed (Finalizado): Entrega efectuada satisfactoriamente.

Filtros en el Cliente

  • La app móvil permite filtrar en tiempo real por cualquiera de estos 4 estados y por sucursal física.

Diagrama de Secuencia 6: Consulta de Sucursales y Navegación GPS Dinámica

Solicitud de permisos de ubicación en tiempo de ejecución, obtención de coordenadas GPS y apertura de Google Maps.

BranchesFragment Location Services Google Maps Intent branches 
sequenceDiagram
    autonumber
    actor C as Cliente
    participant UI as BranchesFragment
    participant PERM as ActivityResultContracts.RequestPermission
    participant GPS as FusedLocationProviderClient
    participant REPO as BranchRepository
    participant API as Supabase REST (/branches)
    participant EXT as Google Maps App (Intent)

    C->>UI: Abre pantalla "Sucursales"
    UI->>UI: checkSelfPermission(ACCESS_FINE_LOCATION)
    alt Permiso No Otorgado
        UI->>PERM: launch(ACCESS_FINE_LOCATION)
        PERM-->>C: Muestra diálogo nativo de permisos del sistema Android
        alt Usuario Acepta
            C->>PERM: Conceder permiso
            PERM-->>UI: Permission Granted
            UI->>GPS: getLastLocation()
            GPS-->>UI: Retorna Location(lat, lng del cliente)
        else Usuario Rechaza
            C->>PERM: Denegar permiso
            PERM-->>UI: Permission Denied
            UI->>UI: Usar ubicación por defecto (Centro de La Paz)
        end
    else Permiso Ya Otorgado
        UI->>GPS: getLastLocation()
        GPS-->>UI: Retorna Location(lat, lng)
    end

    UI->>REPO: getBranches()
    REPO->>API: GET /rest/v1/branches?active=eq.true
    API-->>REPO: Retorna sucursales (Central, Calacoto, El Alto con horarios y teléfonos)
    REPO-->>UI: Lista de sucursales
    UI-->>C: Muestra tarjetas con distancia y botón "Ver en mapa"

    C->>UI: Toca botón "Ver en mapa" de Sucursal Central
    UI->>UI: Intent(ACTION_VIEW, Uri.parse("geo:lat,lng?q=Sucursal+Central"))
    alt Google Maps Instalado
        UI->>EXT: startActivity(mapIntent)
        EXT-->>C: Abre Google Maps con trazado de ruta en tiempo real
    else Sin App de Mapas
        UI->>UI: Fallback a URL web de Google Maps en navegador
        UI-->>C: Abre mapa interactivo en navegador
    end

Manejo Moderno de Permisos

  • Implementación basada en ActivityResultContracts.RequestPermission() conforme a las guías de Android 14+.
  • La app no se bloquea ante la denegación del GPS; continúa operando con las coordenadas de la sede central.

Integración Nativa

  • Lanzamiento mediante Intent explícito con fallback seguro a navegador en caso de no contar con visor de mapas.

Diagrama de Secuencia 7: Panel Administrativo Web, CRUD y Supabase Storage

Gestión de catálogo, subida de imágenes a bucket product-images y propagación en tiempo real al catálogo móvil.

Admin Web (React) Supabase Storage PostgreSQL App Android 
sequenceDiagram
    autonumber
    actor ADM as Administrador
    participant WEB as ProductsView.jsx (Consola Web)
    participant SUPA_JS as Supabase JS Client
    participant STORAGE as Supabase Storage (Bucket product-images)
    participant DB as PostgreSQL (Tabla products)
    participant MOB as App Móvil (Catálogo Cliente)

    ADM->>WEB: Hace clic en "Nuevo Producto"
    WEB-->>ADM: Despliega modal con formulario de producto
    ADM->>WEB: Llena datos (Nombre, SKU, Precio, Stock, Categoría) y adjunta foto PNG
    
    ADM->>WEB: Presiona "Guardar Producto"
    WEB->>SUPA_JS: uploadImage(file, 'product-images/prod_sku.png')
    SUPA_JS->>STORAGE: PUT /storage/v1/object/product-images/prod_sku.png
    STORAGE-->>SUPA_JS: 200 OK (Imagen almacenada en bucket)
    
    SUPA_JS->>STORAGE: getPublicUrl('product-images/prod_sku.png')
    STORAGE-->>SUPA_JS: Retorna https://.../product-images/prod_sku.png
    
    WEB->>SUPA_JS: insertProduct(productData + imageUrl)
    SUPA_JS->>DB: INSERT INTO products (name, sku, price, stock, category_id, image_url)
    DB-->>SUPA_JS: 201 Created (Retorna nuevo producto con UUID)
    SUPA_JS-->>WEB: Éxito en la creación
    WEB-->>ADM: Muestra Toast verde "Producto guardado con éxito" y recarga tabla

    Note over MOB,DB: Sincronización Inmediata con Clientes
    MOB->>DB: GET /rest/v1/products?active=eq.true
    DB-->>MOB: Retorna nuevo producto con URL de imagen en CDN
    MOB-->>MOB: Glide descarga la foto y renderiza la tarjeta en el Catálogo

Manejo de Archivos Binarios

  • Las fotos se cargan directamente en el bucket product-images con políticas de acceso público.
  • La base de datos almacena exclusivamente la URL CDN generada, optimizando el rendimiento de las consultas SQL.

Sincronización Multicanal

  • Cualquier producto creado o editado en la consola web queda disponible de inmediato para todos los clientes en la app móvil.
